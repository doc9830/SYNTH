# Changelog

Все значимые изменения проекта SYNTH. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [Semantic Versioning](https://semver.org/lang/ru/).

## [1.6.0] — 2026-09-27

Озвучка ответов системным синтезом речи: «Озвучить» у ответа ассистента, «стоп» в пределах
абзаца и подсветка того, что читается прямо сейчас.

### Добавлено
- **Озвучка ответов** (`src/lib/ttsText.ts`, `src/lib/tts.ts`, `src/lib/useSpeech.ts`): ответ
  разбирается по абзацам, заголовкам, пунктам списка, цитатам и строкам таблицы — каждый блок
  уходит в движок отдельным фрагментом (до 400 символов, длинный абзац режется по предложениям).
  Блоки кода не читаются: синтезатор произносит их бессмысленно.
- **«Озвучить» / «Стоп» у сообщения ассистента** (`src/ui/MessageItem.tsx`): повторное нажатие по
  читаемому ответу останавливает чтение, новое «Озвучить» глушит предыдущее. Читаемый фрагмент
  подсвечивается в тексте (`src/ui/Markdown.tsx` + `.tts-speaking` в `index.css`), так что за
  голосом можно следить глазами.
- **Нативный плагин `SynthTts`** (`android/app/src/main/java/app/synth/hub/TtsPlugin.java`) поверх
  системного `android.speech.tts.TextToSpeech`: методы `available`/`speak`/`stop`/`shutdown`,
  события `progress`. Разрешения не нужны, микрофон не используется, аудио никуда не уходит;
  голос берётся из установленных на устройстве, по умолчанию русский (среди русских предпочитается
  офлайновый). Если русского голоса нет — кнопки озвучки нет вовсе, и один раз показывается
  понятное сообщение со ссылкой на настройки синтеза речи Android (без краша и «сломанной кнопки»).
  Сетевой голос предупреждает один раз и не блокируется.
- **Веб-версия**: fallback на `speechSynthesis` с русским голосом (ждём `voiceschanged` 1.2 с —
  Chrome отдаёт голоса асинхронно); русского голоса нет — кнопки нет.
- **Освобождение ресурсов**: `stop()` при сворачивании приложения, `shutdown()` при уходе с экрана —
  `handleOnPause`/`handleOnStop`/`handleOnDestroy` в плагине плюс `onAppPause()` в `nativeShell.ts`.
- `<queries>` для `android.intent.action.TTS_SERVICE` в `AndroidManifest.xml`: на Android 11+ без
  этой записи `TextToSpeech` не видит установленные движки и «не находит голос» на ровном месте.
- Проверки `checks/tts.check.ts` (47 проверок): разбор markdown на фрагменты, нарезка длинных
  абзацев без потерь, сопоставление блока с фрагментом для подсветки, тексты сообщений.

### Изменено
- Версия: `1.5.1` → **`1.6.0`**, `versionCode` 9 → **10**.

## [1.5.1] — 2026-09-27

Шапка блока кода: кнопка «Поделиться файлом» больше не уезжает за край на телефоне.

### Исправлено
- **Шапка блока кода на узком экране**: подпись языка обрезается многоточием (`truncate`),
  а группа кнопок («Копировать», «Поделиться файлом») не сжимается и переносится на вторую
  строку, если места не хватает. До этого на телефоне кнопка отправки могла оказаться
  за правым краем (карточка с `overflow-hidden`) и в неё нельзя было попасть.
- Версия: `1.5.0` → **`1.5.1`**, `versionCode` 8 → **9**.

## [1.5.0] — 2026-09-27

Файлы наружу: `.md` из чата теперь уходит системным sheet'ом «Поделиться» — в Telegram, Drive, почту.

### Добавлено
- **«Поделиться файлом» у блока кода** — рядом с «Копировать» (порядок существующих кнопок не менялся).
  Расширение берётся из языка блока: `md` → `.md`, `json` → `.json`, неизвестный язык или обычный
  текст → `.md`. Имя — слаг от первой значащей строки (заголовок/комментарий), пробелы → `-`,
  латиница/кириллица/цифры/`-`/`_`, обрезка до 48 символов; слага нет — `<тип>-<ГГГГ-ММ-ДД-ЧЧмм>.md`.
- **«Поделиться файлами (N)» у сообщения** — 12 md-блоков уйдут 12 файлами в одном вызове
  (`ACTION_SEND_MULTIPLE`). Рядом, а не вместо, — **«одним файлом»**: те же блоки, склеенные
  в один `.md` с разделителями `# Файл 1: имя.md`.
- **«Поделиться чатом (.md)»** в меню «⋮»: front-matter (`title`, `exported`, `model`, `messages`),
  роли `## Пользователь` / `## Ассистент`, tool-раунды (`### Вызов инструмента: …` — аргументы до
  500 символов, `### Результат инструмента` — до 2000 с пометкой «…обрезано»). Вложения — только
  placeholder'ы `![](./attachment-N)` и список имён: base64 в файл не попадает. Имя файла —
  `<слаг-заголовка>-<ГГГГ-ММ-ДД-ЧЧмм>.md`.
- **Одна функция-обёртка** `src/lib/shareFiles.ts → exportMarkdown(files)`: `Filesystem.writeFile`
  в `Directory.Cache`/`exports/` (`recursive: true`, `Encoding.UTF8`, крупные файлы — чанками через
  `appendFile`), `Filesystem.getUri()` и `Share.share({ files })`. Дублирующихся записей в кэш нет.
- **Зависимости**: `@capacitor/filesystem` и `@capacitor/share` — только они; новых разрешений не
  требуется (пишем в кэш приложения и отдаём через `FileProvider` с authority
  `${applicationId}.fileprovider`; `<cache-path>` в `res/xml/file_paths.xml` уже покрывает кэш).
- **Веб и десктоп**: `navigator.canShare({ files })` → Web Share API, иначе скачивание через
  `Blob` + `URL.createObjectURL`. Кнопки не прячутся: фича работает и в браузере.
- **Кэш не растёт**: при следующем экспорте `exports/` чистится от файлов старше 7 дней
  (`stat` + `deleteFile`), за пределы папки очистка не выходит.
- Проверки `checks/share.check.ts` (66 шт.): санитизация имени (слэши, `..`, длинные и злые имена),
  слаг, расширение по языку, разбор fenced-блоков (включая незакрытый во время стрима), 12 блоков
  → 12 файлов, склейка в один файл, структура экспорта чата с лимитами и placeholder'ами,
  вырезание `sk-`-ключей и `Bearer`-токенов. Всего в `npm run checks` теперь 278 проверок.

### Изменено
- Версия: `1.4.1` → **`1.5.0`** (`package.json`, `android/app/build.gradle`), `versionCode` 7 → **8**
  (Android ставит обновление только при большем коде версии).

## [1.4.1] — 2026-09-27

Картинки снова доходят до модели: vision определяется по id, а не «на глазок».

### Исправлено
- **Вложения у `deepseek-v4.1-flash`** — модели по умолчанию в пресете RuAPI. Приложение
  считало её текстовой: на попытку приложить фото отвечало «модель не принимает изображения
  на вход», а сама картинка в запрос не попадала (агенту уходило служебное пояснение).
  Теперь `getModelCapabilities()` знает про vision-семейства (`deepseek-v4`, `qwen*-vl`,
  `gemma-3`, `grok-3/4`, `o3`/`o4`, `pixtral`, `llava`, `internvl`, `moondream`…) и отдельно
  помечает заведомо текстовые и генераторы картинок — `deepseek-chat`, `deepseek-reasoner`,
  `gpt-image-*`, `dall-e`, эмбеддинги, TTS/аудио.
- Если провайдер сам отклоняет изображение (400/415/422 с упоминанием `image_url`, `vision`,
  `multimodal`), в ответе чата видна подсказка — убрать вложение, выбрать vision-модель или
  выключить отправку картинок, — вместо общего «проверьте параметры запроса».

### Добавлено
- **Настройка «Изображения на вход»** — в «Настройках» (вкладка «Подключение») и на втором шаге
  мастера первого запуска: **Авто / Да / Нет**. «Авто» решает по id модели и показывает свой
  вердикт прямо в подписи («Авто · да»), «Да» выручает нестандартные имена моделей у шлюзов и
  локальных серверов, «Нет» гарантированно не отправляет картинки. Настройка переопределяет
  эвристику в обоих местах: и кнопка вложения в поле ввода, и сборка запроса агентом.
- Проверки `checks/vision.check.ts` (30 шт.): распознавание vision-моделей и текстовых
  семейств, ручное переопределение, сборка wire-сообщений (`image_url` с data URL уходит
  в запрос, а у текстовой модели вложение превращается в пояснение) и подсказка при отказе
  провайдера. Всего в `npm run checks` теперь 101 проверка.

## [1.4.0] — 2026-09-27

Claude по соседству: второе подключение — Anthropic Messages API — и шапка без лишних надписей.

### Добавлено
- **Тип подключения «Anthropic (Claude)»** — в настройках подключения и в мастере появился
  переключатель «Тип подключения»: OpenAI-совместимый (по умолчанию) или Anthropic. Запросы идут
  в `POST /v1/messages` с заголовками `x-api-key`, `anthropic-version` и
  `anthropic-dangerous-direct-browser-access`, список моделей приходит из `GET /v1/models`.
  Системный промпт (отдельное поле), `tool_use` / `tool_result` и блоки размышлений переводятся
  внутри `src/providers/anthropic`, поэтому агент, инструменты, память, метр контекста и интерфейс
  работают без изменений. Рисование картинок остаётся за отдельным подключением — Claude их не
  создаёт, и переключение уведёт генерацию на OpenAI-совместимый адрес.
- Проверки `checks/anthropic.check.ts` (71 шт.): заголовки, перевод запроса и ответа, разбор
  SSE-потока (текст, размышления, `tool_use` из `input_json_delta`, счётчики токенов) и сборка
  транспорта — включая то, что OpenAI-путь не изменился.

### Изменено
- Из шапки чата убрана надпись «генерирую…» во время стрима: она сдвигала метр контекста
  («10/32k») и отвлекала. Что модель работает, видно по живой строке статуса в её ответе
  («Думаю…», «Пишу код…») и по кнопке остановки в поле ввода.
- Кнопка **«Настроить»** под полем ввода стала шестерёнкой без текста: она закреплена справа
  от чипов функций, сами чипы прокручиваются по горизонтали. Раньше текстовая кнопка уезжала
  за край узкого экрана и её было не видно. Открывает по-прежнему шторку «Функции».

### Исправлено
- **Выравнивание сообщений**: реплики пользователя снова справа (с видимой рамкой), ответы
  модели — слева; раньше пузырь пользователя мог «съезжать» на всю ширину ленты.
- **Enter на Android переносит строку** вместо отправки — как в мобильных мессенджерах;
  отправка остаётся за стрелкой в поле ввода. На физической клавиатуре и в браузере на десктопе
  Enter по-прежнему отправляет сообщение.

## [1.3.0] — 2026-09-27

Контекст под контролем: в шапке видно, сколько токенов уходит в запрос, и можно задать окно модели.

### Добавлено
- **Метр контекста в шапке чата**: рядом с названием модели — «10/32k» и мини-прогрессбар
  (жёлтый от 80 %, красный от 95 %, `∞` при снятом ограничении). Компактные иконки активных
  функций в строке заголовка заменены на него — функции по-прежнему видны в шторке «Функции».
- **Шторка «Контекст»** (тап по метру): сколько токенов уйдёт в следующий запрос, сколько всего
  накопилось, что обрезано по окну, сколько зарезервировано под ответ и точное число
  `prompt_tokens` из последнего ответа провайдера; пресеты окна 4k / 8k / 16k / 32k / 64k / 128k,
  «∞ без ограничения» и своё значение.
- **Обрезка истории по окну модели** (`src/lib/context.ts`, `src/lib/agent.ts`): если диалог длиннее
  окна, самые старые сообщения не отправляются — системный промпт и память остаются, история
  никогда не начинается с ответа ассистента, последнее сообщение сохраняется всегда.
  Оценка по символам (латиница ≈ 4 символа на токен, кириллица дороже) — токенизатора провайдера
  в приложении нет.
- «Настройки → Подключение → **Размер контекста (токенов)**» — то же значение, что и в шторке «Контекст»;
  `0` — не ограничивать. Для старых сохранений подставляется 32k.
- Проверки `checks/context.check.ts` (34 шт.): оценка токенов, бюджеты, обрезка истории, проценты
  заполнения и разбор настройки окна.

### Изменено
- Меню «⋮» рисуется порталом в `body`: в шапке `backdrop-blur` создаёт свой контекст наложения,
  из-за чего панель теряла фон и часть пунктов оказывалась под лентой сообщений. Теперь панель
  непрозрачная, с непрозрачной рамкой и тенью, а тап мимо закрывает меню прозрачной подложкой
  (убраны `mousedown`/`scroll`-слушатели, из-за которых пункты могли «не нажиматься»).

### Исправлено
- **Фон меню «⋮» больше не прозрачный** — в WebView/Chromium панель под размытой шапкой теряла заливку.
- **Удаление чата из меню шапки**: подтверждение показывается внутри самой панели
  («Удалить чат «…»?» → «Удалить» / «Отмена») вместо системного `window.confirm`, который
  в WebView мог не появиться — нажатие выглядело неработающим. Итог подтверждается тостом.

## [1.2.0] — 2026-09-27

Долговременная память на устройстве и управление функциями прямо из чата.

### Добавлено
- **Долговременная память (локальная)**: факты и предпочтения хранятся в IndexedDB устройства
  и подмешиваются в новые диалоги (лимиты «записей в один запрос» и «символов в промпте»).
  По умолчанию выключена — включается в «Настройки → Функции» или тумблером в шторке «Функции».
  - инструменты модели `remember` / `recall` / `forget` (доступны только при включённой памяти);
  - команда **«запомни, что …»** — запись без обращения к модели, с уведомлением «Запомнил: …»;
  - **авто-факты**: после ответа отдельный короткий запрос вытаскивает устойчивые факты из диалога;
    секреты (ключи, пароли, токены) не сохраняются, близкие формулировки склеиваются;
  - шторка **«Память»** (⋮ → «Память»): список и поиск, правка, закрепление («всегда в контексте»),
    ручное добавление, экспорт `.md`/`.json`, импорт и полная очистка.
- **Шторка «Функции»** — тумблеры возможностей из меню шапки и из поля ввода: веб-поиск,
  чтение ссылок, генерация изображений, калькулятор, текущее время, поиск по чатам, память,
  показ размышлений и вызовов инструментов. Видны зависимости: выключили поиск — гаснет чтение
  ссылок, выключили память — гаснут «Авто-факты».
- **Новые инструменты модели**: `calculator` (проценты, степени, скобки, `sqrt`/`abs`/`min`/`max`/`round`,
  запятая как десятичный разделитель), `current_time` (настоящие дата, время и часовой пояс),
  `search_chats` (поиск по прошлым чатам приложения — локально, без отправки истории наружу).
- **Своё подключение для картинок**: «Как у чата» / «Свой API» (отдельные Base URL и ключ, ключ
  используется только инструментом `generate_image`) / «Через backend» — частый случай,
  когда чат работает на одном провайдере, а картинки на другом.
- Вкладка **«Функции»** в настройках: тумблеры инструментов и секция памяти с лимитами,
  авто-фактами и счётчиком записей.
- Смоук-проверки логики `npm run checks` (`checks/`): реестр функций, память (запись, дедуп,
  секреты, контекст, экспорт/импорт) и калькулятор.

### Изменено
- **Меню в шапке — «⋮»** вместо длинной кнопки: оно прокручивается на низких экранах и содержит
  пункты «Функции» и «Память». Статус-строка показывает значки **всех** включённых функций.
- Функции в поле ввода вынесены в чипы под строкой ввода; кнопка «Настроить» открывает
  шторку «Функции» — включение не требует ухода в настройки.
- Из настроек убраны ручные «проверки» поиска и чтения страниц: они дублировали реальный чат,
  состояние инструментов теперь видно по тумблерам.

### Исправлено
- **Команда «запомни, что …» не срабатывала никогда**: в шаблоне использовался `\b`, а в JS граница
  слова считается по латинице — после кириллического «запомни» её нет. Теперь после глагола требуется
  разделитель, вводное «что» отбрасывается («запомни, что я живу в Казани» → «я живу в Казани»),
  а «чтобы» не съедается.
- Чтение флага функции больше не падает, если раздела настроек нет (старые сохранённые настройки
  без новых секций): отсутствующий раздел считается выключенным.

## [1.1.1] — 2026-09-27

Нативная обвязка Android: установка обновлений, кнопка «Назад», файлы и камера.

### Исправлено
- **Обновление из приложения больше не «просит и молчит»**: сообщение нативного плагина
  проверялось по тексту, хотя `INSTALL_PERMISSION_REQUIRED` — это код ошибки (`error.code`).
  Из-за этого системный экран «Установка неизвестных приложений» **никогда не открывался**.
  Теперь ошибка распознаётся по коду (с запасной проверкой текста), экран настроек открывается,
  а после возвращения в приложение установка **продолжается автоматически** (без повторного
  нажатия «Установить»). Если системного экрана на прошивке нет, приложение подсказывает путь
  вручную: Настройки → Приложения → SYNTH.
- **Кнопка «Назад»** закрывает то, что действительно открыто: шторки «Прикрепить» и выбора модели,
  диалог обновления, выпадающее меню чата, настройки, консоль отладки и сайдбар
  (раньше любая открытая панель — кроме диалогов — приводила к сворачиванию приложения).
- **Кнопка «Камера»** в «Прикрепить» снова открывает съёмку: на Android 11+ без `<queries>`
  для `IMAGE_CAPTURE`/`VIDEO_CAPTURE` WebView не находил приложение камеры и молча открывал
  файловый менеджер.
- **Экспорт чата в `.md` и «Скачать» у картинок работали в браузере, но не в APK**:
  у WebView нет DownloadListener, поэтому `<a download>` ничего не делал. Добавлен локальный
  плагин `SynthFiles` — файлы сохраняются нативно: в Android 10+ картинки в «Pictures/SYNTH»
  (видны в галерее), остальное в «Download/SYNTH», на Android 9− в песочницу приложения.
- **Вложения из галереи/камеры** больше не отбраковываются как «неподдерживаемый формат»,
  если Android не передал MIME-тип файла — тип определяется по расширению (jpg/jpeg/png/webp).

## [1.0.0] — 2026-09-27

Первый публичный выпуск SYNTH (Synthetic Neural & Tool Hub).

### Добавлено
- **Универсальное подключение**: приложение работает с любым OpenAI-совместимым API.
  Мастер первого запуска из двух шагов — Base URL + API key, затем выбор модели для чата
  и (опционально) для изображений. Пресеты OpenAI, OpenRouter, RuAPI, DeepSeek, Groq,
  Mistral, Together, Ollama, LM Studio.
- **Стартовый экран** с объяснением возможностей вместо пустого чата, пока подключение не настроено.
- **Живой стриминг ответа**: текст печатается по мере генерации (раньше ответ появлялся целиком
  после завершения).
- **Мысли модели под катом**: блок «Думаю…» с таймером, автопрокруткой и авто-сворачиванием,
  когда начинается ответ; после завершения — «Размышления модели · 12 с».
- **Фазовые статусы** как в ChatGPT/Claude: «Готовлю ответ…», «Думаю…», «Ищу в интернете…»,
  «Читаю страницу по ссылке…», «Генерирую изображение…», «Пишу код…», «Отвечаю…».
- **Обновления из приложения**: проверка релизов GitHub (не чаще раза в 6 часов, с возможностью
  «Пропустить версию»), диалог «Что нового», загрузка APK с прогрессом и запуск системного
  установщика через локальный плагин `SynthUpdater`. В браузере — переход на страницу релиза.
- Отдельная вкладка «О программе» в настройках: версия, ссылка на релизы, кнопка проверки обновлений.
- Пресеты провайдеров в настройках API; подпись подключения (например, «OpenAI») в сайдбаре.

### Изменено
- **Ребрендинг**: приложение называется SYNTH, `applicationId` — `app.synth.hub`,
  новая иконка-«нейронный хаб» и сплэш-экраны (генератор `scripts/brand.mjs`).
- Провайдерский слой переименован в `src/providers/openai` (это OpenAI-совместимый протокол,
  а не привязка к конкретному шлюзу); заголовок авторизации для proxy-режима — `x-provider-key`.
- Сообщения об ошибках и подсказки стали провайдер-нейтральными.
- Backend-proxy: переменные `PROVIDER_BASE_URL`, `PROVIDER_API_KEY`, `PROVIDER_MODEL`
  (старые `RUAPI_*` поддерживаются для совместимости).
- Отрисовка стрима больше не зависит только от `requestAnimationFrame`: добавлен таймер-страховка
  (~8 обновлений в секунду), чтобы текст печатался и в фоновой вкладке/неактивном WebView.
- Генерация изображений по умолчанию выключена — включается выбором image-модели.

### Удалено
- `ReasoningBlock` — заменён на `ThinkingPanel` со статусами фаз и таймером.
